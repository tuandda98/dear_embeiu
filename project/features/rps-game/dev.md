## Backend (2026-09-13)

### Firestore rules — `firestore.rules` (khối `couples/{coupleId}`, sau `careMessages`)
- 3 helper mới đặt trong khối couples: `rpsPresenceTouchesOnlyOwnKey()` (presence `is map`, `diff(resource.presence).affectedKeys().hasOnly([uid])`, value của mình phải `is timestamp`; create so với `{}`), `rpsStartedAtUnchanged()`, `rpsStatusTransitionAllowed()`.
- `match /games/{gameId}`: read=member · create=member, `hasOnly [type, createdBy, status, createdAt, presence, rematchOf, updatedAt]`, `type=='rps'`, `createdBy==uid`, `status=='invited'`, `createdAt==request.time`, presence chỉ key mình, `rematchOf` non-empty string nếu có · update=member, `hasOnly` thêm `startedAt/cancelledBy/result/finishedAt` (để heartbeat presence trên ván đã finished không vỡ hasOnly), bất biến `type/createdBy/createdAt/rematchOf/result/finishedAt` (so qua `.get('x', null)`), `cancelledBy` nếu có phải == uid; transition: cùng status (startedAt không đổi) | `invited→playing` (chưa có startedAt, `startedAt==request.time`) | `invited→cancelled` (chỉ createdBy) | `invited→expired` (`createdAt < request.time - duration.value(10,'m')`) · delete=false.
- `match /games/{gameId}/moves/{uid}`: read own luôn, read người kia chỉ khi cha `status=='finished'` (get() cha) · create chỉ chủ, `hasOnly [choice, createdAt]`, choice ∈ rock/paper/scissors, `createdAt==request.time`, cha `status=='playing'` + `startedAt is timestamp` + `request.time < startedAt + duration.value(7,'s')` · update/delete=false.
- Additive hoàn toàn (collection mới); không đụng rule khác.

### Indexes — `firestore.indexes.json`
- 2 composite `games` (COLLECTION scope): `type ASC, status ASC, finishedAt DESC` (lịch sử) + `type ASC, status ASC, createdAt DESC` (ván đang mở).

### Cloud Functions — `functions/index.js` (chèn trước helper `sendToRecipientDevices`)
- Hằng/helper: `RPS_CHOICES`, `RPS_BEATS` (rock>scissors>paper>rock), `RPS_ROUND_MS`=5000, `RPS_GRACE_MS`=2000, `RPS_REMATCH_PRESENCE_FRESH_MS`=30s, `RPS_RESULT_PRESENCE_STALE_MS`=20s, `RPS_COPY` vi/en (có `partnerFallback` như `DAILY_QUESTION_COPY`), `buildRpsInviteText`, `buildRpsResultText`, `rpsComputeResult(memberIds, choices)`, `rpsFinishInTransaction(gameRef, memberIds, {requireBothMoves})` (transaction chung, idempotent: đã finished → `{ok:true, already:true}`).
- **`notifyRpsInvite`** onCreate `games/{gameId}` (type rps + status invited): fail-closed nếu creator không phải member; skip khi `rematchOf` trỏ ván có `presence[partner]` tươi <30s (fail-open nếu đọc ván cũ lỗi); inbox `{type:'rps_invite', coupleId, gameId, actorUserId, actorName?}` (actorName bỏ nếu rỗng → client tự fallback) + push data `{type:'rps_invite', coupleId, gameId}`.
- **`resolveRpsGame`** onCreate `moves/{uid}`: transaction đọc game + moves; đủ 2 move của 2 member → `status:'finished'`, `result{winnerUid, choices, reason:'normal'}`, `finishedAt`/`updatedAt` serverTimestamp; thiếu → `waiting_for_moves` (không ghi).
- **`finishRpsGame`** onCall `{coupleId, gameId}`: auth + member (HttpsError unauthenticated/permission-denied/not-found); `status!='playing'` → `{ok:false, reason:'not_playing'}`; chưa tới `startedAt+7s` mà thiếu move → `{ok:false, reason:'too_early', retryAfterMs}`; đủ điều kiện → thiếu = `'none'`, 1 người chọn thắng, cả 2 none hoà, `reason:'timeout'` (nếu cả 2 đã có move thì `'normal'`). Trả `{ok, result, already?}`.
- **`notifyRpsResult`** onUpdate `games/{gameId}` (before≠finished, after==finished, type rps): push tới member có presence CŨ >20s hoặc không có presence; copy theo góc nhìn người nhận (win/lose(tên người thắng)/draw); gọi `sendToRecipientDevices` riêng từng người; KHÔNG inbox. Data `{type:'rps_result', coupleId, gameId}`.
- `PUSH_TYPE_PREF_FIELD` KHÔNG thêm rps (chưa có pref mute riêng, như care_message). Lint: repo không có ESLint config → `node -c index.js` (script `lint`) OK.

### Gotcha / vấn đề mở
- Rules `presence.diff()` trên create so với `{}` qua ternary `resource == null ? {} : resource.data.get('presence', {})` — compile + emulator OK.
- `finishRpsGame` dùng `Date.now()` của server CF để so `startedAt+7s` — lệch clock client không ảnh hưởng (client chỉ gọi, server tự từ chối `too_early`).
- `notifyRpsResult` đo presence bằng `Date.now()` lúc trigger chạy (thường <1–2s sau khi finished) — nếu CF cold-start chậm >20s thì người đang xem có thể vẫn nhận push (chấp nhận).
